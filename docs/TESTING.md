# Тестирование

Три уровня тестов. Главное правило: всё, что касается денег, занятости столов и доступа к данным, проверяется тестами базы, потому что эта логика живёт в базе.

| Уровень | Инструмент | Где | Что проверяет |
| --- | --- | --- | --- |
| База | pgTAP | `supabase/tests/*.sql` | RLS, ограничения, RPC, расчёт суммы |
| Юнит | Vitest | `tests/unit` | Функции на TypeScript: часовые пояса, форматирование денег, валидация |
| E2E | Playwright | `tests/e2e` | Сценарии из `docs/USER_FLOWS.md` в браузере |

## Команды

```bash
supabase db reset && supabase test db   # тесты базы на чистой базе с seed
npm run test                            # Vitest
npm run e2e                             # Playwright, нужен запущенный supabase start
```

CI запускает все три уровня на каждый pull request. Красный CI — мержить нельзя.

## Правила

- Новая таблица — тест, что пользователь другого заведения не читает и не меняет её строки, и что `anon` не читает её напрямую.
- Новая RPC — тест на успешный вызов, на вызов чужим пользователем и на вызов с неверными данными.
- Найденный баг сначала воспроизводится тестом, потом чинится.
- Время в тестах фиксированное. Функции, зависящие от «сейчас», принимают момент параметром (`at`), чтобы тест не зависел от часов.

## RLS и доступ (этап 1 и далее)

- [ ] Администратор заведения A не видит заведение, ресурсы, брони, сеансы, оплаты и гостей заведения B.
- [ ] Администратор не может менять тарифы, карту зала и сотрудников.
- [x] Администратор не читает `audit_log`. Владелец читает.
- [x] Никто не может изменить или удалить строку `audit_log`.
- [ ] `anon` не читает ни одну таблицу напрямую.
- [ ] `get_public_venue` не возвращает неопубликованное заведение.
- [ ] `get_public_venue` и `get_availability` не возвращают имена и телефоны гостей.
- [ ] `create_public_booking` нельзя вызвать с ролью `anon`, только с сервера.

## Расчёт суммы (этап 3)

Демо-тарифы для тестов: «День» 1 500 ₸/ч, будни 10:00–18:00; «Вечер» 2 500 ₸/ч, будни 18:00–02:00; «Выходные» 3 000 ₸/ч, сб–вс 10:00–02:00.

- [x] 1 час днём в будни = 1 500 ₸.
- [x] 17:00–20:00 в будни = 1 × 1 500 + 2 × 2 500 = 6 500 ₸ (смена тарифа внутри сеанса).
- [x] Пятница 23:00 — суббота 01:00 = 2 × 2 500 = 5 000 ₸ (переход через полночь остаётся в тарифе пятницы).
- [x] 40 минут днём = 1 000 ₸.
- [x] Пауза 30 минут посреди часа игры не оплачивается.
- [x] Перенос со стола пул на русский стол с другим тарифом: каждый отрезок по тарифу своего стола.
- [x] Время вне всех тарифов — ошибка `no_tariff`, а не 0 ₸.
- [x] Два подходящих тарифа — берётся с большим `priority`.
- [x] Пакет «3 часа за 5 000 ₸», игра 3,5 часа днём = 5 000 + 750 = 5 750 ₸.
- [x] Округление до 15 минут: 61 минута днём считается как 75 минут = 1 875 ₸.
- [x] Выключенный тариф не применяется.
- [x] Время в UTC переводится в часовой пояс заведения, а не сервера.

Тесты: `supabase/tests/06_calc_amount.test.sql`.

## Сеансы и касса (этап 4)

- [x] Нельзя запустить второй сеанс на занятом столе, даже двумя одновременными вызовами.
- [x] Пауза закрывает отрезок `play` и открывает `pause`; продолжение — наоборот.
- [x] Перенос на занятый стол отклоняется.
- [x] `close_session` записывает `time_amount`, `items_amount`, `total_amount` и `tariff_snapshot`.
- [x] Изменение тарифа после закрытия не меняет сумму закрытого сеанса.
- [x] Оплата без открытой смены отклоняется.
- [x] `expected_cash` при закрытии смены = `opening_cash` + наличные оплаты смены, без отменённых.
- [x] Аннулирование сеанса и отмена оплаты пишутся в `audit_log` с автором.

## Брони (этапы 5–6)

- [x] Две брони на один стол с пересечением времени — вторая отклоняется ограничением.
- [x] Бронь, начинающаяся в момент окончания другой, проходит, если буфер 0.
- [x] С буфером 15 минут бронь через 10 минут после окончания предыдущей отклоняется.
- [x] Отменённая, завершённая и `no_show` бронь не занимает стол.
- [ ] `get_availability` не показывает окна, занятые бронями, буфером и открытыми сеансами с `expected_end_at`.
- [ ] Открытый сеанс без `expected_end_at` закрывает стол для онлайн-брони.
- [ ] `get_availability` не показывает окна раньше `min_lead_min` и позже `max_days_ahead`.
- [ ] `get_availability` учитывает часы работы через полночь.
- [ ] `get_availability` не показывает ресурсы с `bookable_online = false` и заведения с выключенной онлайн-бронью.
- [ ] `create_public_booking` создаёт бронь сразу в статусе `confirmed`.
- [ ] Повторная онлайн-бронь с тем же телефоном находит существующего гостя, а не создаёт нового.
- [x] `mark_no_shows` переводит `confirmed` в `no_show` после `no_show_after_min`, если сеанса нет.
- [x] `get_day_bookings` возвращает верное число прошлых неявок гостя.
- [ ] Отмена по токену проходит до начала брони и отклоняется после.
- [ ] Неверный токен не возвращает никаких данных.
- [ ] Лимит активных онлайн-броней на один телефон и на один IP срабатывает.
