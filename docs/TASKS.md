# Этапы разработки

Девять этапов, разбитых на подэтапы. Каждый подэтап заканчивается тем, что можно проверить: автотестами и руками в браузере. Для защиты мидтерма хватит этапов 0–6 на демо-заведении из seed.

Дизайна пока нет: используем стандартные компоненты shadcn/ui без своей темы. Когда появится `docs/DESIGN.md`, тему применим отдельной задачей.

После этапа 1 схема базы устоялась, и работу можно делить: один ведёт админку (этапы 2–5), второй публичную страницу (этап 6). Миграции создаёт один человек за раз, изменения схемы согласовываются.

## Как идём по подэтапам

1. Ветка на подэтап: `stage-N.M-название`, например `stage-1.2-auth`.
2. План и вопросы, потом код. Код не пишем, пока план не одобрен.
3. Подэтап закрыт, когда проходят все пункты «Проверка»: автотесты зелёные и ручная проверка сделана.
4. Отмечаем подэтап здесь, дописываем «Отличия от плана», если были, мержим в `main`.

Обычно подэтап устроен так: сначала база и pgTAP-тесты (логику можно проверить без интерфейса), потом экран поверх неё. Список тест-кейсов в `docs/TESTING.md`, сценарии в `docs/USER_FLOWS.md`.
